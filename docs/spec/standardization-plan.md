# План уніфікації UI та контенту

Мета: один набір значень і компонентів на весь сайт. Еталон значень — [design-system.md](design-system.md).
Принцип: **спочатку токени й компоненти, потім міграція сторінок, потім захист від регресій**.
Кожен етап — окрема гілка від `main` і окремий PR, щоб зміни легко ревʼювати.

## Стан на зараз (аудит `src/`)

| Що | Факт |
|----|------|
| Секції | 29 файлів із `<section>`, 11 варіантів `className`; стандартний `pt-14 md:pt-16 lg:pt-20` у 11, кольорові з `mt-14…` у 9, решта відхиляються (наприклад `mt-24 … lg:mt-32 lg:py-24`) |
| H2 | 8 різних комбінацій розмірів; стандарт 20/28/34 має 14 із 29 |
| H1 | 8 різних комбінацій (від 22 до 50 px, `leading` від 0.98 до 1.2) |
| Кнопки | 15+ варіантів (включно з `text-link`) рядка класів: розміри `px-4…px-7`, `py-3…py-4`, відступи `mt-6…mt-12` зашиті всередині |
| Розмір тексту | 27 різних `text-[Npx]`; допустима шкала має 6 значень (10–15) |
| z-index | 10 різних значень: 1, 2, 10, 20, 30, 40, 80, 90, 100, 120 |
| Токени | `font-display` дублював `font-sans` (вже прибрано), `line-height` 1.3 (вже виправлено) |

## Етап 0. Рішення (прийняті)

| # | Питання | Рішення |
|---|---------|---------|
| 1 | H1 внутрішніх сторінок | **28 → 34 → 40 px**, `leading 1.1`. Hero головної окремо: 36 → 48 |
| 2 | Секції з великими відступами | **Звести до стандарту**, варіанта `loose` немає |
| 3 | Шкала тексту | **10 / 11 / 12 / 13 / 14 / 15** + лід 16 / 20. Рідкісні 8, 9, 17, 18, 19, 21, 22, 24, 26 зводимо до найближчого |
| 4 | Звернення до клієнта | **«ви»** (з малої) |
| 5 | Кнопки | **4 варіанти:** `filled`, `outline`, `light` (на фото), `text-link`; розміри `md` і `sm` |
| 6 | Регістр | У даних і коді **звичайний регістр** («Дивитись усе»), caps лише через CSS (`u-label`, заголовки) |
| 7 | Формат ціни | **1 200 грн** (нерозривний пробіл, «грн» після числа) |
| 8 | Повторювані тексти | **Файл-словник у `src/data`** (кнопки, помилки, порожні стани) |

Наслідки для наступних етапів:
- `Section` не має `spacing="loose"`, тільки `default` і `flush`.
- `Button` має `variant`: `filled` | `outline` | `light` | `text-link`. Пару кнопок у `InstagramReels` переводимо на `filled` + `outline`.
- Етап 4: тексти сайту перевіряємо на форму «ви» і безособові формулювання, у словнику фіксуємо єдині варіанти.
- `formatPrice` уже повертає «1 200 грн», змін у коді не потрібно; лише перевірити, що роздільник тисяч нерозривний.

## Етап 1. Токени та примітиви в `globals.css`

Результат: усе повторюване живе в одному місці.

1. Типографічні утиліти за роллю: `.u-h1`, `.u-h2` (20/28/34, 1.1), `.u-h3`, `.u-lead`, `.u-body` (13px, `leading-relaxed` 1.625, `muted`), `.u-small` (11–12px, `muted`). Наявні `.u-display`, `.u-subheading`, `.u-label` лишаються основою.
2. Токени відступів секції як CSS-змінні (`--section-gap`, `--section-pad`) і/або утиліти `.u-section-gap`, `.u-section-pad`.
3. Шкала `z-index` через токени: `--z-content`, `--z-overlay-controls`, `--z-header`, `--z-drawer`, `--z-modal`, `--z-toast`. Зіставити з наявними 10 значеннями.
4. Змінні для тривалостей і easing (`--ease-soft`, `--dur-fast/base/slow`) замість значень у кожному класі.
5. Оновити [design-system.md](design-system.md), додавши нові назви утиліт.

Перевірка: `npm run type-check`, `npm run build`, візуально головна не змінилась.

## Етап 2. Компоненти-обгортки

Результат: сторінки не пишуть класи вручну.

| Компонент | Пропси | Замінює |
|-----------|--------|---------|
| `ui/Section` | `tone` (`white`, `mist`, `sand`), `spacing` (`default`, `flush`), `id` (додає `scroll-mt`) | 29 `<section className=…>` |
| `ui/Button` | `variant` (`filled`, `outline`, `light`, `text-link`), `size` (`md`, `sm`), `fullWidth`, `href` (рендер `Link`), без зовнішніх `mt-*` | 15+ рядків класів |
| `ui/SectionHeading` (розширити) | `label`, `title`, `description`, `href`, `align`, `as` | ручні блоки «eyebrow + h2 + p» |
| `ui/PageHeading` | H1 внутрішніх сторінок, 28 / 34 / 40 px | 8 варіантів H1 |
| `ui/Text` (за потреби) | `size` (`body`, `small`), `tone` | ручні `text-[13px] … text-muted` |
| `ui/Field` | обгортка label + input + error із `ContactForm`, `checkout` | дублікати `fieldClass` |

Правило: зовнішні відступи (`mt-*`) задає контейнер, а не сам компонент, щоб компонент не тягнув за собою «свій» відступ.

## Етап 3. Міграція сторінок (пакетами)

**Статус:** пакети 3.1–3.7 виконані на гілці `feature/design-tokens`. Залишились відкритими вертикальні відступи контейнерів сторінок (див. design-system.md, «Відомі прогалини»).

Порядок від найбільш видимих до менш. Після кожного пакета — візуальна звірка mobile / tablet / desktop.

1. **Головна** (`homePage/*`, `app/page.tsx`): виправити відомі розбіжності (H2 30/36, `mt-3` в `InstagramReels`, `mt-9/10/12`, ширини абзаців) і перейти на `Section`, `SectionHeading`, `Button`.
2. **Спільні блоки** (`shared/*`): `Faq`, `ContactForm`, `Footer`, `Header`, `CartDrawer`, `SearchOverlay`, `ProductCard`: кнопки, розміри тексту, `z-index`.
3. **Каталог і товар** (`catalogPage`, `productPage`, `sizeGuidePage`).
4. **Кошик і оформлення** (`checkoutPage`, `favoritesPage`): форми через `Field`.
5. **Контентні сторінки** (`aboutPage`, `deliveryPage`, `contactsPage`, `blogPage`, `blogArticlePage`).
6. **Юридичні** (`legalPage`: offer, privacy): одна типографіка довгого тексту (стилі для `h2`, `p`, `ul` у статті).
7. **Службові:** `not-found`, стани завантаження й помилок.

Критерій завершення пакета: у файлах немає довільних `text-[Npx]` поза шкалою, `py-*/mt-*` на секціях і копій рядків кнопок.

## Етап 4. Контентні правила та тексти

1. Файл `docs/spec/content-guidelines.md`: довжини заголовків і абзаців, формат ціни («1 200 грн»), регістр і пунктуація в кнопках, форма звернення, лексика (джерело: `instagram-content-export.md`, `marketing-structure.md`).
2. Словник повторюваних текстів у `src/data/` (кнопки, підписи, стани): «Дивитись усе», «Додати в кошик», помилки форм, повідомлення успіху.
3. Порожні стани: кошик, «Обране», пошук без результатів, товар не в наявності, помилка завантаження, з єдиним шаблоном (заголовок, пояснення, кнопка).
4. Правила для фото: співвідношення сторін (3:4 товар, окремо hero і блог), формат, вага, шаблон `alt`.
5. Прогнати всі сторінки по правилах, виправити тексти.

## Етап 5. Стани та доступність

1. Єдиний `focus-visible` для всіх інтерактивних елементів (глобальне правило в `globals.css`).
2. Стани кнопок і полів: hover, focus, disabled, error, loading.
3. Перевірка контрасту `muted` на `mist` і `sand` (11–13px `muted` на `sand` може не дотягувати до WCAG AA; за потреби затемнити токен).
4. Перевірка `prefers-reduced-motion` на всіх нових анімаціях.

## Етап 6. Захист від регресій

1. ESLint-правило або скрипт-перевірка: заборона довільних `text-[Npx]` поза шкалою, `z-[N]`, HEX-кольорів у компонентах.
2. Розділ «Чого дотримуватись» у [CLAUDE.md](../../CLAUDE.md): посилання на design-system, заборона нових одноразових значень.
3. Чекліст PR (`.github/pull_request_template.md`): «Використано `Section`/`Button`/токени».
4. Опційно: сторінка `/design` (закрита від індексації) із каталогом токенів і компонентів замість Storybook, і скріншот-тести ключових сторінок.
5. Lighthouse / PageSpeed після міграції: переконатися, що зелений результат із критеріїв готовності не постраждав.

## Ризики

- Візуальні зсуви після зведення відступів і розмірів: перевіряти кожен пакет на трьох ширинах.
- Секції з унікальними макетами (hero, `VyshyvankaSpotlight`, `ToysCollection`) не намагаємось втиснути в шаблон: стандартизуємо тільки відступи й типографіку.
- Не змішувати міграцію з новими функціями, щоб diff лишався читабельним.
